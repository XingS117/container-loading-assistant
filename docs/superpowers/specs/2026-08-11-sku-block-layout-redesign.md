# SKU 块布局重构设计（装柜方案助手）

日期：2026-08-11
状态：草案（待用户审阅）
关联：5 个大模型方案对比（豆包/DeepSeek/Kimi/Gemini/腾讯）、打印稿与历史反馈

## 1. 背景与目标

用户以同一货单（5 SKU / 69 托 / 18.7t）对比了 5 个大模型装柜方案与本系统，发现：
- 5 个大模型方案**高度一致**：双层堆叠（15 底位 × 2 层）+ **每 SKU 集中成块** + 重货定位 + 门端/尾部缓冲——这是行业主流做法。
- 本系统当前：装得多=混合铺满（托盘按体积散排，布局杂乱）、更稳妥=网格重量居中、易操作=SKU 块分步——**三方案差异靠混合/网格/分区，未对齐"每 SKU 成块"的主流共识**；且无门端缓冲（装满整个柜长）。

目标（用户要求"全面稳妥、系统真正成熟"）：
1. **SKU 块布局**作为核心模型：每个 SKU 的货物集中成块、块内网格排布、双层堆叠——满足 **5+ SKU**、**纯整托/纯散箱/混装** 全部场景。
2. **三方案重新定义**（保留三方案，差异清晰）：装得多=装载率优先、更稳妥=SKU 块配平（重货居中）、易操作=SKU 块分步。
3. **默认门端缓冲** 300mm（可配置，牺牲约 2-3% 装载率换装卸便利）。
4. 保留现有正确性边界：完整支撑、校验器、少装披露、API 契约。

## 2. 现状与问题

- `_layer_layout`（分层铺满）：托盘带（网格/rectpack）+ 散箱端区；托盘按重量/体积混合，非 SKU 块。
- `_pallet_grid_layout`：仅同尺寸整托。
- `_stable_balance_layout`：SKU 块配平（上一轮新增），但仅纯整托不可叠。
- 无门端缓冲：柜长全部用于装载。
- 三方案对纯整托：装得多=rectpack 托盘带（柜头）、更稳妥=网格居中、易操作=band 分区——**布局仍非"每 SKU 一块"的主流形态**。

## 3. 设计

### 3.1 SKU 块（Block）模型

每个 SKU 的货物（同尺寸栈）构建为一个块：

```
Block:
  sku_id
  cargo (CargoSpec)
  unit_footprint: (length_mm, width_mm)   # 栈的 footprint（含朝向选择）
  unit_height_mm                          # 单件高
  layers: int                             # 叠高层数（1=单层，2=双层；受柜高/承重/可叠约束）
  columns: int                            # 块内列数（沿柜宽）
  rows: int                               # 块内行数（沿柜长）
  block_length_mm                         # = rows × length + gaps
  block_width_mm                          # = columns × width + gaps
  total_pieces                            # = columns × rows × layers（截断后=实际件数）
```

块参数推导（每 SKU）：
- `layers`：由柜高 − 缓冲、`max_layers`、`max_top_load_g`、可叠性决定（同 SKU 自叠）。
- `columns` = `(usable_width + gap) // (unit_width + gap)`（最多列数，至少 1）。
- `rows` = `ceil(件数 / (columns × layers))`；底位 = `columns × rows`，每底位叠 `layers` 件；最后底位可能不足 `layers`。
- 块长超可用柜长 → 拆块（见 3.4 兜底）或允许少装并披露。

朝向：每 SKU 在 `allowed_orientations` 内选择"占宽最小"的 footprint（对齐腾讯"摆向已优化为占宽最小方向朝向柜宽"），受柜门宽约束。

### 3.2 块放置与门端缓冲

- **可用柜长** = `inner_length - 2×clearance - door_buffer_mm`（`door_buffer_mm` 默认 300，写入 PackRequest 可选字段；0 = 不留）。
- 块按放置顺序沿柜长依次摆放（从柜头到柜门），块间留 `item_gap`。
- 放置顺序由方案策略决定（见 3.3）。
- 柜门端剩余空间（缓冲 + 装不满的余量）在 `warnings`/`cons` 披露（如"柜门预留操作空间约 30cm"）。

### 3.3 三方案（重新定义）

| 方案 | 块放置顺序 | 块内特征 | 语义 |
|---|---|---|---|
| 装得多 | 按**体积/件数降序**（大块先、靠柜头） | 列数最大（装载率）、layers 最大 | 装载率优先 |
| 更稳妥 | 按**块总重量从柜长中心向外**（重块居中） | 列数适中 + 行内蛇形（y 配平） | 重心最优（对齐 Kimi 重心核算） |
| 易操作 | 按 **SKU 输入顺序**柜头→柜门 | 每块一步装载 | 操作最简、便于清点 |

配平（更稳妥）：
- 块按重量从柜长中心向外放（重 SKU 居中、轻 SKU 两端）。
- 块内行蛇形（奇偶行反向）：柜宽方向 y 向重量均衡。
- 双层：同 SKU 自叠（重下轻上由块重量定位 + 可叠约束保证）。

### 3.4 兜底与边界

- **块长超可用柜长**：
  - 装得多：块拆成多个子块（按列拆分）或回退 `_layer_layout`（分层铺满，散箱大订单装载率最优）。
  - 更稳妥/易操作：拆块；仍放不下 → 按"体积最小的 SKU 先删"少装并披露（必装不删）。
- **纯散箱大订单**（如 630 件单 SKU）：装得多=分层铺满（现有，装载率高）；更稳妥/易操作=SKU 块（每 SKU 一块，超长拆块）。
- **混装**：托盘块 + 散箱块统一成块（托盘按整托 footprint，散箱按栈 footprint），块放置同一策略。
- **校验器**：`validate_solution` 不变（完整支撑、边界、重量、层数、承重）——块内同 footprint 垂直叠天然 100% 支撑。
- **少装披露**保留：`unloaded_counts` + `warnings`（如打印稿 PB 未装 3 件）。

### 3.5 契约与前端

- `POST /api/v1/pack` 请求：新增可选 `door_buffer_mm`（默认 300；0 关闭）。其余字段不变。
- 响应：`placements`/`zones`/`metrics`/`pros`/`cons`/`warnings` 结构不变；`metrics` 增加门端缓冲披露（或放入 `warnings`）。
- 前端无需改动（3D/俯视/侧视/打印基于 placements 与 zones）。

## 4. 测试计划

1. **5 SKU 全整托**（用户案例 69 托）：三方案全装、SKU 块化（每 SKU 一个 zone）、门端缓冲生效、重心（更稳妥最居中）、通过校验器。
2. **纯散箱多 SKU**：装得多=分层铺满（装载率 ≥ 现状）、更稳妥=SKU 块配平、易操作=SKU 块分步。
3. **混装**（托盘+散箱）：托盘块 + 散箱块、块放置策略生效、散箱上托（重下轻上）保留。
4. **门端缓冲**：door_buffer_mm=300 时装载率约降 2-3%、柜门剩余空间披露；=0 时行为不变。
5. **块超长兜底**：超大 SKU 拆块/回退/少装披露。
6. **回归**：现有 20GP/40GP/40HQ、易碎/不可叠/必装、间隙/边距、性能（大订单 < 15s）全量通过。

## 5. 范围外

- 不做多柜拆分、跨柜优化。
- 不引入重型依赖（ortools 等），只用 rectpack + stdlib。
- 不改变前端视觉（除非需要展示门端缓冲标注）。

## 6. 验证方式

- 本地：新增场景测试（见第 4 节）+ 全量 pytest + 前端 build。
- 公网：部署后真实 `POST /api/v1/pack` 三方案核对（SKU 块、重心、门端缓冲）。
