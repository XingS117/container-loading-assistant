# AI 目标感知的紧凑装柜布局设计

## 目标

解决两个用户可见问题：

1. AI 返回 JSON 的格式稍有变化时被误判为“AI 返回内容无法识别”。
2. 布局图出现明显内部空洞，且三种方案没有充分体现不同的业务目标。

系统应保持物理安全和可解释性，同时让 AI 参与候选生成，而不是只在结果末尾做装饰性排序。

## 三种方案的目标边界

三种方案分别优化，不共用同一个件数规则：

- **装载率优先（high_fill）**：最大化装入件数；件数相同后最大化货物体积和底层连续覆盖，尽量减少内部空洞。
- **重心稳妥（stable）**：必须保持装载率优先方案的货物集合；在不减少件数的前提下，优先重心平衡、完整支撑和底层连续性。
- **易操作（easy）**：只允许减少非必装货物；在有限减少范围内优先连续分区、较少货区、较少装卸步骤和较小内部空洞。实际少装数量和原因必须写入结果 warning。

易操作方案的默认少装上限为装入件数的 5%，至少允许比较 1 件，但不得删除必装货物。只有当少装后的紧凑性指标明显改善时才接受少装，否则沿用保持件数的候选。

## AI 策略契约

AI 仍然只返回策略，不返回坐标。兼容旧字段，并增加目标差异化建议：

```json
{
  "sku_order": ["sku-a", "sku-b"],
  "orientations": {"sku-a": "LWH"},
  "row_groups": [["sku-a", "sku-b"]],
  "profiles": {
    "high_fill": {"row_groups": [["sku-a", "sku-b"]]},
    "stable": {"row_groups": [["sku-b", "sku-a"]]},
    "easy": {"zone_order": ["sku-a", "sku-b"], "max_zones": 3}
  }
}
```

- 所有 ID、朝向、分组和 profile 字段都必须经过白名单校验。
- 缺失或非法的 profile 建议只影响对应方案，不影响其他方案和本地基线。
- 旧版只返回 `sku_order`、`orientations`、`row_groups` 时，解析器将其作为通用策略继续兼容。

## AI 返回解析与降级

解析器按以下顺序尝试：

1. OpenAI 兼容响应的 `message.content` 字符串或结构化片段。
2. `message.parsed`、工具调用参数和 `reasoning_content` 中的最终 JSON。
3. Markdown 代码块或夹杂说明文字中的最外层 JSON 对象。

如果提供商因不支持 `response_format=json_object` 返回 HTTP 400，则自动以同一提示重试一次但不携带该参数。只有解析、配置、网络或服务错误时才降级；不会因 AI 失败阻塞本地安全算法。

策略状态区分：AI 已采纳、AI 已返回但未形成安全候选、AI 解析/请求失败后使用本地算法，并记录可诊断错误类型。

## 候选生成与评分

每个 profile 都生成至少两类候选：

- 本地确定性基线候选。
- 使用该 profile 的 AI 顺序、朝向、行组和区域建议生成的 AI 引导候选。

所有候选都必须经过现有物理校验。坐标只由本地算法产生；AI 不得绕过边界、柜门、碰撞、间隙、承重、层数、易碎和完整支撑规则。

候选评分按 profile 分开：

- `high_fill`：装入件数、体积利用率、底层连续覆盖率、内部空洞面积、最大空隙、重心。
- `stable`：装入件数、重心偏差、完整支撑、底层连续覆盖率、内部空洞面积。
- `easy`：紧凑性、货区数、装卸步骤、区域连续性、重心；件数只作为“少装上限”内的次级指标。

增加水平紧凑化/填洞候选：只允许在同一支撑关系下做安全平移、同排贴合或重排，不改变堆叠层级。每次变换后重新执行 `validate_solution()`。

## 数据流

1. 前端提交订单和可选 AI 配置。
2. 后端请求一次目标感知策略，并解析为通用策略及 profile 策略。
3. 本地算法分别生成 high_fill、stable、easy 候选。
4. 物理校验器过滤不安全候选。
5. 每个 profile 按自己的评分和件数边界选出结果。
6. API 返回三套布局、AI 实际采纳状态、少装披露和紧凑性指标。

## 测试验收

- 解析标准 JSON、代码块 JSON、结构化 JSON、工具调用参数、reasoning 字段和含说明文字的 JSON。
- 模拟不支持 `response_format` 的提供商，确认自动重试后 AI 状态为可用。
- AI 引导候选必须影响至少一个合法布局选择，并且不能降低 high_fill/stable 的装入件数。
- easy 可以在非必装场景少装，但必须满足少装上限、保留必装货物并返回明确 warning。
- 截图类似的多 SKU 混装订单中，三套方案全部通过物理校验；high_fill/stable 保持件数，easy 的内部空洞和货区/步骤优于保持件数候选或明确回退。
- A/B/C、四 SKU、五 SKU、散箱、必装、易碎、间隙、复杂订单超时和现有前后端回归继续通过。

## 非目标

- 不让 AI 直接生成可执行坐标。
- 不以提高 AI 采纳率为理由放宽任何物理安全约束。
- 不引入外部优化求解器、数据库或新的运行时依赖。
