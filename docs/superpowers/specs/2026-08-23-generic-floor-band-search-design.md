# 自定义整托排组搜索设计

## 背景

预置三 SKU、四 SKU、五 SKU 案例有明确的客户排组模板，因此结果通常能保持底层连续和上层集中。自定义组合主要进入通用二维装箱候选链，容易得到物理安全但不符合客户习惯的布局。

## 目标

- 自定义纯整托组合也能生成“底层优先、上层集中、同 SKU 连续”的候选。
- 每个候选仍由现有 `validate_solution()` 做最终物理校验。
- 不改变正式 API、3 个方案 ID 和现有预置模板优先级。
- 不引入 AI SDK 或新的运行时依赖；AI 只作为后续可选的排组策略推荐层。

## 方案

在纯整托候选链中增加通用排组搜索：

1. 为每个 SKU 计算通过柜门、柜体和叠放约束的横放/纵放选项。
2. 对每个 SKU 的底层件数，从满足全部数量的最小支撑底数到全部单层件数生成有限候选。
3. 将各 SKU 的底层件拆成完整行和余数行；余数行按宽度尝试合并为同一排，支持两种规格并排。
4. 按策略生成多种柜头到柜门顺序：按 SKU 区域、按底面积、按重量，以及卸货顺序。
5. 只在同一 SKU 的底层货位上按柜长中心向两侧选择上层支撑，优先完整行，避免孤立单托。
6. 用现有布局质量评分排序，硬规则失败的候选直接丢弃，软规则不足的安全候选继续保留并披露 warning。

预置模板仍在通用搜索之前执行，客户已确认的固定排组不会被覆盖。

## 质量与回退

- 硬规则：越界、碰撞、支撑不足、跨规格叠放、超层数、超承重和必装不完整均拒绝。
- 软规则：底层连续覆盖、上层中部集中、SKU 连续、重心居中用于评分，不阻断安全结果。
- 通用排组没有可行候选时，继续使用既有网格、`rectpack` 和分层回退链。

## 后续 AI 接口边界

AI 只接收结构化货物参数、历史模板摘要和候选质量指标，返回经过 schema 限制的排组策略。后端将策略转换为候选并再次执行物理校验；AI 超时、不可用或返回非法策略时回退到确定性算法。AI 不直接输出或写入最终坐标。

## 验收

- 至少覆盖 3 组非预置纯整托混合组合。
- 结果均通过 `validate_solution()`。
- 底层件数大于上层件数时优先采用连续底层。
- 上层只出现在同规格底层支撑上，并优先形成中部连续区。
- 同一请求多次计算结果稳定，且原有预置案例回归不变。
