# AI 引导的受限装柜规划设计

## 目标

让有效 AI 策略在候选生成前参与 SKU 顺序、合法朝向和行级混排建议，并让复杂订单在固定时间预算内返回物理安全的方案，而不是因组合搜索超时返回 504。

## 边界

- AI 只提供建议，不生成或裁决坐标。
- `validate_solution()`、必装、柜体、柜门、承重、层数、支撑和间隙仍是硬约束。
- AI 建议不可解析、与输入不一致或无法通过本地校验时，忽略该建议并使用确定性受限搜索。
- 不引入外部求解服务或运行时。

## 策略契约

AI 返回紧凑 JSON：

```json
{
  "sku_order": ["sku-a", "sku-b"],
  "orientations": {"sku-a": "LWH"},
  "row_groups": [["sku-a", "sku-b"], ["sku-c"]]
}
```

- `sku_order`：柜头到柜门的 SKU 优先顺序。
- `orientations`：每个 SKU 的首选允许朝向。
- `row_groups`：建议同排出现的 SKU，最多两个不同 SKU；并不表示可跨 SKU 叠放。
- 解析器删除未知、重复或无效项；只保留合法建议。

## 候选生成

1. 先按 AI 建议构造一个确定性的底层优先候选：首选朝向、SKU 顺序、行组和中部上层规则全部由本地代码落实。
2. AI 引导候选通过物理校验后，作为三套方案的共同安全基线；`stable` 仅做安全的重心调整，`easy` 仅做安全的区域/步骤调整。
3. 通用本地搜索保留为回退，但给每次调用固定候选上限；达到上限后返回当前最佳已验证候选，不继续做笛卡尔展开。
4. 若未找到任何物理安全候选，才保留现有不可行错误。软布局目标不再导致请求失败。

## 可观测性与体验

- AI 连接测试请求与实际策略请求使用同一 JSON 结构契约。
- 响应状态区分“AI 建议已采纳”“AI 建议已获取但未能构成安全候选”“AI 不可用，使用受限本地搜索”。
- `AIStrategyStatus` 返回已采纳的建议和模式，前端显示 AI 实际影响的 SKU 顺序、朝向和行组数。
- 服务日志记录供应商、模型、耗时、策略是否采纳和本地候选预算结果，不记录 API Key 或完整货物数据。

## 验收

- 五 SKU 订单在 AI 启用和 AI 不可用两种情况下均返回 3 套物理安全方案，且不返回 `CALCULATION_TIMEOUT`。
- AI 有效时，引导候选的底层 SKU 顺序和合法朝向与建议一致，或状态明确说明未采纳原因。
- 复杂订单的通用搜索达到预算后返回最佳安全候选并增加现场复核 warning。
- A/B/C、四 SKU、五 SKU、散箱、必装、易碎、间隙和现有 API 回归保持通过。
