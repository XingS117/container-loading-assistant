# 装柜系统升级优化实施计划

日期：2026-09-13
依据：[设计规格](../specs/2026-09-13-system-usability-upgrade-design.md)及产品算法审计报告。

## 第一阶段：输入与计算闭环

1. 在 `App.tsx` 增加快速开始入口、测试案例入口和装载目标选择；高级模型设置默认收起。
2. 在 Excel 导入和 `CargoTable` 中增加单位、尺寸、数量、重量和必填字段校验，并输出可逐项修复的数据质量报告。
3. 扩展 `api.ts` 的错误结构，区分输入错误、计算超时、服务错误和本地结果；前端显示阶段进度、耗时和可执行的重试建议。
4. 保留现有三方案 API 契约，确保目标选择可以传递到后端；为每套方案返回目标、状态和软目标未满足说明。
5. 增加必要的前后端测试：空输入、单位错误、超时、三目标提交和旧请求兼容性。

验收：测试案例无需手工配置模型即可完成；错误能定位到具体字段；超时不再只显示“订单较复杂”。

## 第二阶段：布局质量与结果解释

1. 在后端评分中加入大空洞、连续支撑、重心、碎片度和操作成本指标，沿用本地边界、碰撞、支撑和承重校验。
2. 明确三方案的权重和取舍，确保 `stable` 抑制大空洞与悬空，`easy` 优先连续区域和装载顺序，`high_fill` 保持装载率目标。
3. 扩展 `models.py` 和前端 `types.ts` 的结果摘要，提供指标、风险、推荐理由和目标差异。
4. 在 `SolutionWorkspace` 和 `LoadVisualizer` 增加方案对比、货物/区域定位和风险解释；先完成只读闭环，再实现编辑。
5. 用现有测试案例和至少一组脱敏真实订单建立回归基线，记录装载率、空洞面积、支撑率、合法性和计算时长。

验收：每套方案都能说明为什么这样排、空隙是否有风险以及牺牲了什么；所有展示布局通过本地物理校验。

## 第三阶段：仓库执行与人工修正

1. 根据最终坐标生成柜门到柜尾的装载步骤，标出方向、重货、易碎品和固定提示。
2. 增加锁定、旋转、交换、删除和拖拽后的本地校验；支持只对受影响区域局部重算。
3. 完善打印/PDF内容，加入方案目标、风险摘要、步骤清单和复核签名位。
4. 增加保存订单、复制历史订单和剩余货物记录，为后续一票多柜做数据准备。

验收：仓库人员可以只看打印结果完成装载，并能追溯人工调整前后的合法性和差异。

## 第四阶段：数据闭环与后续扩展

1. 增加输入完成率、计算成功率、超时率、方案切换、导出、人工调整和用户反馈事件。
2. 建立脱敏评测集和版本对比报告，模型暂不作为本计划前置条件。
3. 根据真实数据再评估一票多柜、运输成本、叉车通道、绑带点和包装强度约束。

## 发布策略

每一阶段独立提交、测试和灰度验证；先发布输入和解释能力，再发布编辑能力。部署前必须完成前端构建、后端测试、接口回归、真实服务健康检查和一条完整浏览器流程验证。

## 不在本次范围

暂不更换模型、暂不部署新的模型 Key、暂不重写现有 3D 引擎，暂不引入无法由真实案例验证的复杂优化目标。
