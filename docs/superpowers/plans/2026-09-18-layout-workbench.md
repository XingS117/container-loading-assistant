# 装柜工作台改造

目标：用可直接操作的画布替代页面下方零散编辑。保持三种方案与本地安全规则，不能以预览代替安全确认。

## 第一阶段：直接编辑
- [x] 使用全屏工作台，左侧货物单件列表，中间联动视图，右侧坐标、朝向、检查结果；窄屏折叠侧栏。
- [x] 复用 Three.js OrbitControls 和 TransformControls。区分浏览与移动，保留抓取偏移；点击不得移位，取消拖动不得提交。
- [x] 每套方案独立草稿、单件和同 SKU 整组移动、锁定、撤销、重做、恢复及精确坐标输入。
- [x] 后端新增有请求大小及频率限制的布局检查接口，复用 validator、metrics、zones；拒绝悬空、碰撞、承重和非法朝向，返回问题货物 ID。
- [x] 编辑草稿经校验后才能应用。结果、打印、锁定重算使用应用后的坐标；新计算结果清除旧编辑状态。
- [x] 说明反馈尚未传给算法；不再声称重算会采用反馈文字。

## 第二阶段：智能辅助
- [ ] 空隙和配重问题定位，候选调整预览、前后指标比较，用户明确应用；无改善候选不得宣称优化成功。
- [ ] 文字要求转策略须有独立契约和采纳证据，AI 不豁免物理校验。

## 验收
- [x] 后端回归：正常编辑、悬空、碰撞、承重、重复标识、边距、柜门、无效输入、限流。
- [x] 前端回归：撤销重做、三方案隔离、拒绝失败检查、过期请求不覆盖新草稿、应用及打印一致。
- [x] 桌面和 390px 真浏览器：生成结果、进入工作台、选择、拖动、校验、应用、打印；3D 非空、拖动与相机不冲突。
- [x] 全量测试与构建通过后才发布；公网重走编辑接口和页面流程。

文件：`LayoutWorkbench.tsx` 负责会话和面板，`LoadVisualizer.tsx` 复用渲染及视图，`workbench.ts` 负责纯编辑变换，`layout_review.py` 复用后端物理检查。`SolutionWorkspace.tsx` 负责应用后的三方案状态与输出。
