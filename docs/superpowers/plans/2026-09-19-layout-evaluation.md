# 布局质量评测基线

目标：完成 9 月 13 日计划中可复现的离线评测与版本对比能力；如实记录真实订单和现场认可证据的缺口。

沿用 Python、Pydantic、pytest；不引入依赖，不改变生产求解器、API、UI、AI 配置或数据上报。使用现有工作区并保留用户未跟踪文件。用户已授权连续执行、提交推送，无需逐项确认。

方案比较：单独增加单元断言无法追踪布局质量；直接采集生产订单会引入隐私与服务器持久化变化。本轮采用本地显式导入脱敏请求、固定案例 JSON、独立进程运行、JSON/Markdown 报告的最小方案。

- [x] 1. 数据与来源：整理六 SKU 历史复现、五 SKU 客户模板、安全约束、5000 件及 30 SKU 压力案例。使用统一匿名 ID，保留物理参数；未证实订单与测试重量明确标注；不伪造人工认可。
- [x] 2. 自动评测：独立进程限时运行三方案，重复运行，校验安全、件数/重量/步骤数据一致性；从坐标计算底层/上层包围范围内空白面积与最小直接支撑率，记录求解耗时、校验耗时、布局指纹。先写测试并确认失败。
- [x] 3. 版本比较：输入指纹、预算、重复次数、运行环境与指标版本匹配才比较；按方案输出差值和混合取舍，不给未经定义的综合得分。保留失败/超时案例，缺失案例使比较不完整。新增脱敏请求导入命令和使用文档。
- [x] 4. 验证与交付：运行完整前后端测试、构建、五案例重复评测、基线自对照；提交可查报告和运行命令、推送 GitHub。工具为离线研发能力，不重启无改动的生产服务。检查当前公网健康与版本未变。

文件：`backend/evaluation/{__init__,__main__,metrics,runner}.py`、`backend/evaluation/cases/*.json`、`backend/tests/test_evaluation.py`、`docs/evaluations/README.md` 及日期报告。

口径：空白面积是每个相同底面高度的货物平面外接矩形减矩形并集，包含边缘凹口/设置间隙，不等于封闭孔洞或可继续装货面积。上层取最大片层空白。直接支撑率是底面与恰好接触的下层顶面并集交叠率；无上层为 null。它与完整安全校验分开，不能推断运输稳定性或现场满意度。计算耗时仅指本地求解，不包含模型/网络/排队；进程硬超时包括启动与评测。

验收缺口：现有文件没有可核验的真实发货单及现场人工认可布局。导入能力可完成，但真实现场认可需后续实际订单与反馈，不能仅靠当前用例宣布该条款全部完成。
